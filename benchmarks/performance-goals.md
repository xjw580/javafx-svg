# 性能目标与优化顺序

当前阶段结果见 [按需缓存与跨库实测](motion-cache-2026-10-24.md)：已补齐完整像素与静态空闲基准，降低首次光栅和变换分配；FX CPU、完整显示分配与部分功能仍未达标。完整像素结果包含快照读回，屏幕实际呈现延迟尚未测量。

本库的首要性能目标是持平或超过 fxsvgimage，接近或持平 JSVG JavaFX。这是后续优化与验收的方向，当前实测尚未全面达成。

## 对照基线

- 第一基线：fxsvgimage。常用 SVG 的完整显示成本、FX 线程 CPU、分配与交互流畅度应持平或更优，不能只以单项 pulse P95 达标代替整体目标。
- 进阶基线：JSVG JavaFX。优先缩小静态内容显示、批量实例和像素复用场景中的 CPU、分配差距。
- JSVG AWT 继续作为兼容性和性能参考，不替代 JSVG JavaFX 的目标地位。
- 优化需要保留原生 JavaFX CSS、FXML、样式更新和现有动画能力；缓存应在尺寸或内容变化时正确失效，画质与内存代价必须记录。

## 必须分开评价的场景

| 场景 | 评价重点 |
| --- | --- |
| 独立解析与共享文档创建 | 创建耗时、分配，分开记录复用条件 |
| 首次完整显示 | 解析、对象创建、CSS/layout 和首次实际绘制，不能用创建 API 返回时间替代 |
| 完全静态显示 | 初次绘制后的空闲 CPU、分配、保留内存；不能用外部旋转测试替代 |
| 静态内容移动、旋转和缩放 | CPU、分配、pulse 尾部、缓存命中与重建、缩放画质 |
| 修改颜色、描边和尺寸 | 更新成本、重绘正确性与缓存失效 |
| SVG 内部动画 | 相同动画语义下的 CPU、分配、pulse 尾部及生命周期 |

每个场景单独报告与两个基线的差距。维持相同输入、尺寸、缩放、功能效果和明确的缓存策略；不以降低画质、漏画或停播换取未说明的优势。不将 FX 线程分配称为总内存，不将 pulse 称为呈现 FPS。

## 当前优先级

1. 补齐首次完整显示、完全静态显示的跨库基准，并区分独立文档和共享文档；当前 [实测](library-current-2026-10-24.md) 尚不能回答这两类场景的完整成本。
2. 使用采样定位本库 FX CPU 与分配热点，优先处理高频临时对象、重复样式/布局工作和静态内容复用；再评估具体缓存方案。
3. 改善渐变创建成本，并保持纯色、动画、CSS 更新和画质回归通过。
4. 每项优化分别提交，使用统一协议重新比较 fxsvgimage 与 JSVG JavaFX，明确改善、回退及仍未达成的项目。

现有 500 图标渐变外部旋转中，本库 FX CPU 为 2.78 ms/pulse、分配约 300 KiB/pulse，JSVG JavaFX 为 1.06 ms/pulse、约 32.3 KiB/pulse；内部 SMIL 中本库为 4.13 ms/pulse、约 376 KiB/pulse，fxsvgimage 为 1.60 ms/pulse、约 142 KiB/pulse。这些是当前优先调查的差距，不代表完全静态或首次绘制的开销。

## 验证要求

独立 JVM 重复、相同预热和测量条件、逆序或轮换顺序、全部原始数据与失焦记录继续保留。先验证画面与动画正确，再解释性能；创建与渲染测试不与编译或其他基准并行。

“持平”需要在明确场景、可接受差距和重复性证据下判断，不以单次最好值或区间重叠直接断言等效。当前没有指定统一的百分比容差，报告实际差距与完整波动，不自行宣布目标已经达成。
