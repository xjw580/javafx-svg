# 1.0.0-rc 发布候选说明

状态：**准备候选，不是已公开发布**。版本采用本次请求中的 `1.0.0-rc`；它是预发布版本，不代表 SVG 全规范覆盖，也不是正式 `1.0.0` API 稳定承诺。没有因为生成版本号或产物就创建远程 tag、GitHub Release、推送或上传 Maven 仓库。

## 基线与本轮范围

本轮从 `codex/svg-compatibility-20261025` 的 `7e35a44eec3aa69b8fd1672c1f3666d8d47d36cc` 准备；该提交已包含路线阶段 1–6。RC 整理重点是 API 契约、模块/打包身份、版本、独立 Java/Kotlin 消费者和支持范围一致性，而不是继续扩展 SVG 功能。

基线能力包括：

- 卷积与指定光照网格重采样；四通道 component transfer 和 16 种 blend 模式。
- 文档内及受控 PNG/JPEG 的 feImage、feTile、本地 filter 模板。
- 径向渐变二维变换与焦点圆、显式 pattern 可见溢出。
- 普通水平 LTR 文字的逐字位置/旋转、嵌套 textLength；有界静态 CSS 子代/兄弟/属性选择器；白名单滤镜参数 SMIL 动画。
- 原生 JavaFX 演示共 38 个条目，其中 11 个路线示例；源代码、编辑器及离线素材保留在完整源码交付中。

本轮的 README 修正移除上述已实现特性的旧“不支持”陈述，同时保留真正的组合边界。阶段 6 Python 工具新增显式 `--jar` 并默认从本地 POM 解析产物，避免版本改名后误用 SNAPSHOT 或源码 JAR；仅运行参数/路径测试，不重新启动长时间测量。旧 Windows PowerShell 基准脚本继续保留，其 RC 显式路径参数见 [协议](../benchmarks/roadmap-stage6/README.md)。具体 API 审查和变更见 [API 契约](../benchmarks/release-api.md)。

## 坐标与使用方式

候选坐标：

```xml
<dependency>
    <groupId>club.xiaojiawei</groupId>
    <artifactId>javafx-svg</artifactId>
    <version>1.0.0-rc</version>
</dependency>
```

**当前不保证公共 Maven 仓库存在这个版本。** 准备阶段从本源码构建并安装到本地仓库，再用独立消费者工程依赖它：

```shell
mvn clean verify
mvn install
# Linux 无显示器的软件测试环境：
mvn -Pheadless clean verify
mvn -Pheadless install
```

要求 JDK 21+、Maven 3.8.8+；Kotlin 2.2.0，JavaFX 21.0.8。字节码目标为 Java 21。库只保留 Kotlin 标准库和 JavaFX graphics/base 运行依赖；controls、FXML、JUnit、Monocle 与 Demo 不是库运行时依赖。JavaFX 原生库必须匹配部署平台；JavaFX 运行环境与字体由应用提供。不能将编译目标误解为已验证全部更高版本 JDK 或全部平台。

完整源码中的 Demo 使用 `mvn -Pdemo test-compile exec:java`。单独候选 JAR 是类库，不包含 Demo 入口或依赖，不是独立安装程序。详见 [Demo 说明](../demo/README.md)。

## 模块与产物身份

候选 manifest 使用 `Automatic-Module-Name: club.xiaojiawei.svg`，并记录实现名称和版本。它是**自动模块**，不是包含 `module-info.class` 的显式 JPMS 模块；不能声称所有内部实现已通过模块边界封装。模块路径消费者验证应使用该名称，不依赖从文件名推导出的模块名称。不要将同一 JAR 同时重复放入 classpath 和 module path。

打包计划为 `javafx-svg-1.0.0-rc.jar`、`javafx-svg-1.0.0-rc-sources.jar`、对应 POM、文档与校验和。源码附件包含库的 Kotlin 源码，不把测试/Demo 素材塞进主 JAR，也不伪造空的 Javadoc 附件。完整源码交付另保留测试和演示。构建设置固定 `project.build.outputTimestamp` 用于可复现 ZIP 时间戳；最终是否逐字节可复现仍以实际双构建和哈希结果为准。

这些产物不等于已满足 Maven Central 所有要求：项目许可证已明确为 MPL-2.0；最终发布元数据、文档附件策略、签名和目标仓库凭据仍需确认。当前不配置会自动上传的 deployment 目标，也不把本地安装当作公开发布。

## 兼容性与边界

- RC API 以 [契约清单](../benchmarks/release-api.md) 的显式公开类型为准。Kotlin `internal` 类/成员及编译器生成的 `$default`、mangled/synthetic helper 不是承诺给 Java 消费者的接口；自动模块不能把它们变成稳定 API。
- 既有构造器/data-class 行为应保持，新增接口需有消费者检查；不承诺任意旧 SNAPSHOT 到本候选的二进制兼容。重新编译依赖本库的 Java/Kotlin 应用，不复制编译器生成的调用细节。
- `SvgView` 创建、布局、JavaFX 属性和动画控制在 FX 线程操作；解析及受控资源加载可在后台做。详情以 API 契约为准。
- 不执行脚本/事件处理器；DTD、外部实体仍禁用；外部资源默认关闭，显式解析器也不能绕过解析、解码、引用、像素与工作量预算。
- 严格模式不是完整 SVG 验证器。未检测到诊断不等于规范全覆盖；宽松回退不等于完整支持。
- 复杂连写、双向/垂直排版、嵌入字体、文字位置列表动画、外部独立 SVG feImage、filterRes、CSS 伪类/转义/命名空间及 CSS 滤镜参数动画等仍不支持。foreignObject 只提供明确的受限 XHTML 子集，不是浏览器。
- `overflow=visible` 图案采用 SVG 2 建议合成次序，规范仍有未完全规定部分；外部焦点渐变与其他实现存在像素差异，不声明浏览器逐像素一致。

## 验证证据的使用方式

本候选已执行的验证见 [RC 验证记录](VALIDATION.md)；最终逐字节复现与完整日志随交付包提供。

2026-10-26 的阶段 6 基线记录为全量 806 项通过、实际 Demo 38 项通过及 300 秒/6000 次持续编辑通过。这些是**历史基线数据**，不能冒充本 RC 修改后的干净构建或消费者验证。基线累计补丁首次复验出现一次编辑器样例等待超时，原样聚焦和全量重跑通过，但未确认根因；不能称为“从未失败”。历史日志随阶段 1–6 交付包保留。

基线同版本计时主实验和唯一预登记长预热诊断都未形成稳定性能基线，因此不发布“性能提升”或代码性能回退结论。有限持续编辑通过不证明无内存泄漏。历史渲染和 Demo 验证是 Linux Monocle 软件后端，不是 Windows/GPU/真实 HiDPI 验证；本轮只有实际执行并记录的环境可列为已验证。

本 RC 的最终构建、打包身份、Java/Kotlin/模块消费者、补丁复现以及未执行项应记录于独立 RC 验证报告。运行记录尚未产生前，检查表中的项目不应标为完成。`javafx-ui` 的真实项目接入还需要独立执行，不能用最小 Java/Kotlin 消费者代替。
