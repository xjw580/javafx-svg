# RC 发布检查表

此表是放行要求，不是执行日志；未附实际结果的条目不得解释为已通过。

## 可以在准备阶段完成

- [ ] 确认远端基线、完整源码身份与工作区隔离；不覆盖其他人的更改。
- [ ] 版本、候选 Maven 坐标、JAR manifest/模块名称一致；排除平台 classifier、测试、Demo 和机密文件混入主产物。
- [ ] 审查显式公开 API，保留已有构造/copy 语义并记录 RC 边界；独立编译运行 Java 与 Kotlin 消费者。
- [ ] 对实际打包 JAR 检查依赖和模块路径可用性，而非只在测试源码的 classpath 中检查。
- [ ] 最终源码干净全量构建；在干净基线上应用补丁后重建，对照源码及类文件身份。
- [ ] README、Demo、API 契约与代码的支持/限制一致；历史测量不写成本次验证。
- [ ] 检查主 JAR、POM、源码及可用文档产物；记录 SHA-256、构建环境、所有失败与未执行项。
- [ ] 检查 Demo 启动/示例仍可用；不得把静态 PNG 当作实际应用验证。
- [ ] 保存 RC 验证报告与可复现命令，明确有界测试与平台范围。

- [x] 所有者选择与 javafx-ui 一致的 MPL-2.0；原标准 LICENSE 和项目 NOTICE 已添加，第三方图标许可保持原样。POM/产物内许可文件的一致性仍以最终打包检查为准。
- [x] 按 javafx-ui 选择 GitHub Releases：标签触发、Temurin 21、内置 GITHUB_TOKEN；不部署 Maven Central 或私有 Nexus。远端实际权限仍待执行验证，详见 GITHUB_WORKFLOW.md。
- [ ] 明确授权公开 tag / GitHub Release / Maven 上传 / 分支推送的实际操作范围。
- [ ] 完成 `javafx-ui` 的真实接入验证，或明确将它列为 RC 已知未验证项；最小消费者不能替代。
- [ ] 如需支持声明，另行完成授权环境下的 Windows/GPU/HiDPI 验证；未执行就保留限制，不伪装通过。

- [ ] tag 指向已验证的精确提交；Release 明确标为 prerelease，说明已知限制与验证范围。
- [ ] 上传文件与已验证产物校验和一致；验证目标仓库/下载地址真实可用。
- [ ] 检查精确提交的 CI/check/workflow；没有检查不等于 CI 通过。
