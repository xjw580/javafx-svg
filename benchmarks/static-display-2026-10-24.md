# 完整像素结果与静态空闲基线：2026-10-24

本报告使用“立即建立静态缓存”的本库 JAR，SHA-256 为 `735646FE7E1E1B7EF7661D66E8D59338113175555B2D68111F5F487BD74F2E86`，对应 78f76a9 的核心实现。后续策略改动必须另测，不覆盖本基线。

本次补足此前只测创建或外部旋转的缺口：完整光栅结果包含解析、建节点、CSS/layout、延迟 Canvas/skin、快照绘制和像素回读。**本库在这项基线中明显慢于 fxsvgimage，不能根据旧创建表宣称完整显示成本已持平。** 完全静止时，各库 FX CPU 中位数都低于本次计数分辨率，没有证据说明 JSVG 的空闲 CPU 必然更低。

## 协议

Windows 11、JDK 25.0.1、JavaFX 21.0.8、512 MiB 堆；本库、fxsvgimage 1.7.3、JSVG JavaFX 2.2.0，各三个独立新 JVM，共九个。按计划轮换模式顺序、偶数轮反转类型。使用相同内存 SVG 和完整 classpath，每批 500 个独立文档、24px 图标；关闭自动播放及应用 Node.cache，内部缓存保持各自默认。运行期间没有编译、其他基准或 JFR。

每类型至少 5 个批次并持续预热 10 秒，再测 5 批。光栅结果为异步 740×650 逻辑像素快照，计数结束后逐个检查 500 个图标，未通过则整个进程失败。全部 18 个类型/进程组合及每批像素验证通过，保留 90 个正式批次及所有预热。每类型五批先取进程内中位数，再汇总三个独立进程的中位数和全部范围。

这不是冷 JVM 启动，也不是屏幕实际呈现延迟；包含快照/读回及其调度等待，不能视为纯 SVG/GPU 绘制耗时。首次 Scene 图像的完整成本在该协议下可比较，不代表任意界面中首次显示或持续重绘的速度。光栅快照无可见窗口、逻辑比例 1；随后静态窗口采用设备缩放 1.5，不能合并两者绝对成本。

单位：ms/500 个图标，分配为 MiB/批。wall 显示三个进程的中位数 [最小–最大]；CPU 和分配为三个进程中位数。进程 CPU 包含 FX、渲染和其他进程内线程，可能超过 wall；MXBean 分配不含原生内存/显存，不是保留内存。

本库纯色 wall 中位数约为 fxsvgimage 的 2.44 倍，渐变约 3.11 倍。三次进程各自的范围也提供，不能仅挑最好的一次。JSVG 的创建轻不等于完整光栅结果必然更快：在此协议纯色约 197 ms、渐变约 200 ms，均高于 fxsvgimage；这些数据没有测实际呈现 FPS。

4/18 个类型/进程组合触发迭代/预热趋势提示，全部保留。固定预热并非稳态证明；不能将 wall 与 FX CPU 的差值直接断言为 GPU 时间，也没有证据将偏差全归因于缓存、GC 或 JIT。针对缓存建立时机的因果验证和后续改动应使用同协议单列比较。
